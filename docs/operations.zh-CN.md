# 生产部署与运维

## 拓扑和边界

浏览器 → HTTPS Nginx → 单实例 FastAPI（8200）→ 已授权 SSH 资产。
FastAPI → 独立 PostgreSQL；独立迁移任务负责 DDL。

运行一个应用实例、一个 Uvicorn worker。当前活动连接保存在所属进程，启动时会将遗留会话标记为中断。横向扩容需要共享连接控制和分布式实例租约，当前不支持。

生产使用可受支持的 Linux、Docker 和 PostgreSQL，使用固定版本依赖。当前 `requirements.lock` 来自 Python 3.10 验证环境；Docker 使用 Python 3.12，应在目标环境执行同一套验收及依赖扫描。升级依赖后重新测试并更新锁文件。xterm.js 为本地固定版本 5.5.0，许可证保存在 `static/vendor/XTERM-LICENSE`。

## 安全配置

- `PUBLIC_ORIGIN` 必须匹配用户实际访问源（协议、域名及非默认端口）。公网访问必须 HTTPS，`COOKIE_SECURE=true`。MFA 默认关闭，由管理员在用户管理中逐个绑定并开启；旧的 `REQUIRE_MFA` 环境变量不再决定登录策略。
- PostgreSQL 不暴露公网。Docker 的应用端口绑定宿主回环地址，仅 Nginx 对外服务。
- 生产数据库使用独立运行账号；只授予业务表必要 DML 和序列权限，`audit_logs` / `recordings` 只允许 SELECT、INSERT。运行账号不得拥有表、迁移权限或超级权限。
- 迁移账号与运行账号分离。不要把迁移密码、Docker 套接字、宿主目录等挂载到应用容器。Compose 将迁移放在独立服务中。
- `.env` 权限限制为部署用户读取。Windows 可使用目录 ACL 限制；Linux 使用 `chmod 600 .env`。
- 对 SSH 目标进行出口网络白名单限制，只允许需要的资产端口；管理接口限定管理网络。资产配置需要管理员权限，管理员能配置网络目标，应视为高信任角色。
- 不盲信 `X-Forwarded-For`。当前 `--no-proxy-headers` 保留直接对端地址，反向代理后应用审计 IP 为代理 IP。真实客户端 IP 应从可信 Nginx 日志关联，后续如启用代理头必须明确设置可信代理，不能信任任意来源。

## 初始化与恢复 MFA

```sh
docker compose exec app python -m jump_ssh.cli create-admin admin
docker compose exec app python -m jump_ssh.cli reset-mfa username
```

MFA 重置是本地运维高权限操作，会关闭 MFA、清除旧密钥、注销用户已有登录并记录审计。恢复后用户可用密码登录，再由管理员在“用户管理”中重新绑定。后台绑定须在 10 分钟内验证一次验证码，未确认绑定不会强制要求 MFA。启停 MFA 会注销该用户的其他登录，管理员操作自身时保留当前会话。对初始密码和 MFA 配置使用独立安全渠道交付。不要将 URI 放进普通日志、工单附件或聊天群。

## 备份恢复

1. PostgreSQL 使用定时 `pg_dump -Fc` 或基础备份与 WAL 归档，频率按业务 RPO 确定。
2. 单独加密备份 `MASTER_KEY`，限制读取；数据库备份本身不包含解密密钥。
3. 定期在隔离环境恢复数据库，验证凭据和录像可解密，并实际登录测试资产。
4. 数据库备份与密钥备份不要存放在同一未受控目录；使用异地受控备份和访问审计。
5. 数据库升级、迁移和依赖升级前先备份，先在预发布环境验收。

恢复时使用匹配的 `MASTER_KEY` 与数据库。不要通过重新生成 MASTER_KEY 尝试恢复；这会导致旧数据无法解密。当前未实现自动密钥轮换，轮换必须编写并验证全量重加密流程。

## 审计留存与容量

录像逐段加密存入 PostgreSQL，默认每会话输出上限 20 MiB，到达上限会终止会话，不会绕过录制继续连接。普通交互模式输入不单独持久化，但远端终端回显仍会被录像；启用命令策略的 SSH/TELNET 会话另外加密记录逐条命令及拦截事件，见[详细使用手册](user-guide.zh-CN.md)。只允许管理员、审计员读取录像，读取本身记录操作日志。

禁止应用更新、删除和清空审计表。留存清理由独立 DBA 按制度执行归档、验证和分区维护；当前尚未提供自动归档、WORM 存储或删除作业。制定留存周期，监控数据库增长，不能无限期无容量规划地运行。

## 监控与停机

- `/health/live`：应用响应；`/health/ready`：数据库及用户表可查询。
- 监控容器状态、数据库连接数、磁盘、备份结果、登录失败、会话失败及 SSH 上游可达性。
- 健康检查须提供与 PUBLIC_ORIGIN 相符的 Host，Compose 已配置。
- 维护重启会断开当前 SSH，会话记录为中断。先通知用户并清空活动会话，再执行升级。
- `docker compose down` 停止服务但保留数据库卷；不要使用 `down -v`，除非明确要销毁独立数据库且已验证备份。
