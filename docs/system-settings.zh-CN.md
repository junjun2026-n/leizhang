# 系统配置

管理员登录后打开“系统配置”。普通运维人员和审计员没有此菜单，后台接口也会检查管理员权限。

## 平台外观

- 平台名称：同步显示于侧栏、页面标题及浏览器标签，登录页同样使用此名称。
- 平台说明：显示于侧栏。
- LOGO：选择 PNG、JPEG 或 WebP 图片（源文件最多 5MB），页面自动压缩至最长边 256px。压缩后最多 32KB，可预览或移除。
- 风格：明亮、深色；支持自定义主题色。
- 字体：系统默认、微软雅黑、宋体、等宽字体；字号支持 12～20px。实际字体取决于访问设备安装情况。

点击“保存外观”后立即应用并持久化；仅点击预览不会保存。已打开的其他客户端刷新页面后加载新设置。登录前公开接口仅返回外观设置，不返回数据库或密码信息。

## 数据库配置

页面分别显示当前连接和待生效配置，支持主机、端口、数据库名、用户、密码和 SSL 模式。

“测试连接”会实际连接 PostgreSQL，并检查平台数据表是否存在；不会切换当前数据库。密码留空保留已配置密码，更换主机、端口或账号需要重新填写密码。密码不在读取接口或审计记录中返回。

更换数据库步骤：

1. 备份原库及 `MASTER_KEY`，将原有用户、资产、授权、外观设置、审计与录像等数据迁移到目标 PostgreSQL。保留原有主密钥，否则已加密凭据、MFA 和录像无法解密。
2. 使用迁移账号对目标库执行 `python -m jump_ssh.cli migrate`，通过 `MIGRATION_DATABASE_URL` 指定目标连接。运行账号应有业务表权限，审计和录像表保持只追加权限。
3. 在系统配置中填写目标运行账号，测试连接后保存。目标库缺少平台数据表时拒绝保存。连接测试不等于全部业务权限和数据完整性检查。
4. 重启堡垒机，再检查 `/health/ready`、登录、资产访问与录像。重启会断开当前 SSH 会话。

数据库配置写入项目 `.env`，不会自动迁移数据、创建角色或重启服务；当前进程继续使用原库直到重启。数据库修改会记录审计事件。服务进程需要有写入 `.env` 的权限。容器或服务管理器若通过环境变量注入 `DATABASE_URL`，需同步调整该环境变量，因为环境变量优先于 `.env`。

`start.ps1` 对项目本地数据库执行启动与升级；使用外部数据库时只检查已迁移的数据表，不自动启动本地 PostgreSQL，也不使用运行账号执行迁移。
