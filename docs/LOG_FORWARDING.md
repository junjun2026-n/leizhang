# 日志转发

在“系统配置 → 日志转发”页签设置接收服务器 IPv4/IPv6、端口和传输格式。新增角色权限 `settings.logging`（查看及修改日志转发配置）；管理员默认具有权限，其他角色须在权限管理中明确分配。此权限不自动授予数据库配置或外观配置权限。

支持 UDP、TCP、TLS；JSON、Syslog RFC 5424、自定义单行模板。默认关闭，启用后才能编辑接收端及测试发送。保存立即生效。“测试发送”使用页面参数并发送测试事件，不自动保存；保存与测试操作均记录操作审计。UDP 无接收确认，需要在接收端核实。

转发范围为操作审计和 SQL/协议/终端操作审计的元数据，包括事件编号、时间、动作、操作者 ID、目标、客户端 IP，以及协议、会话 ID、操作 ID、成功状态、耗时和行数。不会转发原始 SQL、命令正文、账号密码、资源凭据、录屏、文件内容或协议审计 `detail` 原文。会话的创建、结束等已有操作审计按原事件转发。

首次保存从当前日志位置开始，不补发已有历史。暂停保留进度，再启用会继续转发暂停期间仍在库中的记录。发送失败显示错误并自动重试；重启从数据库里的游标继续。数据库切换后使用目标数据库中的配置和游标。每次发送成功后保存进度，数据库提交失败可能导致重发，请按 `source + id` 去重。接收端落盘确认不属于当前协议能力。

TCP/TLS 使用 UTF-8 换行分帧，每条一行；不使用 octet-counted 分帧。TLS 依赖系统信任库，验证证书链及接收服务器 IP SAN；不会绕过证书校验。后台线程与业务请求独立，发送超时为 2 秒，失败后约 5 秒重试。当前与堡垒机原部署要求一致，使用单应用实例。

Syslog 使用 Facility 0–23、informational 级别和 JSON 消息。模板字段：`{id}`、`{time}`、`{source}`、`{action}`、`{actor}`、`{target}`、`{ip}`、`{detail}`、`{hostname}`、`{platform_name}`。`{{` 和 `}}` 表示花括号；禁止属性访问、表达式、格式化及模板换行，事件文本中的控制字符转义输出。

状态页显示成功发送条数、最近发送时间与最近错误。“刷新状态”不会发送测试或更改配置。凭据、密钥与未脱敏内容不应放入模板或目标字段。
