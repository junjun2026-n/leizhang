# 平台权限管理

## 分配步骤

1. 使用内置管理员，或已被分配“分配角色平台权限”的账号登录。
2. 进入“角色管理”创建所需角色；也可使用已有角色。
3. 进入“权限管理”，在“角色”下拉框选择目标角色。角色列表中的“分配平台权限”也可直接跳转。
4. 按功能分组勾选权限，确认页面显示的已选项。
5. 点击“保存平台权限”。
6. 在“用户管理 → 角色 / 启停”将角色分配给对应用户。
7. 相关用户重新登录，验证可见菜单和可执行操作。

权限通过角色分配，一个用户使用一个角色。同一角色的用户共享平台权限；需要不同范围时应创建不同角色。用户级命令黑／白名单仍在原入口单独配置。

角色的管理员、运维人员、审计员类型用于提供初始默认权限。配置平台权限后，以实际勾选的权限为准，可以为运维类型角色分配审计查看权限，也可以将自定义管理员类型角色限制为只读。升级前未自定义权限的角色保留原有默认功能。

## 功能分组

| 分组 | 可分配权限 | 说明 |
| --- | --- | --- |
| 总览 | 查看总览 | 统计范围仍受资源、会话的数据范围限制 |
| 资产 | 查看授权资产、查看全部资产、新增及修改资产 | 管理资产包含录入和修改资产配置及初始账号信息 |
| 系统账号 | 管理全部资源系统账号 | 新增、修改、启停和删除资源账号，查看所需授权信息 |
| 连接范围 | 免账号授权连接全部启用资源 | 高权限项；仍须满足资源访问审批、账号启用、命令策略等要求 |
| 连接与会话 | 连接资源、查看自己的会话、查看全部会话、终止自己的会话、终止全部用户会话 | 查看全部会话不会自动获得终止全部会话权限 |
| 审计 | 查看全部会话录像、命令审计、SQL / 协议审计、操作审计 | 不同审计入口分别授权；这些是查看全平台相关记录的权限 |
| 用户 | 查看用户、创建及分配角色和启停、管理 MFA、修改用户命令策略 | 查看用户不等于能修改用户或 MFA |
| 角色与权限 | 查看角色、新增编辑删除角色、分配角色平台权限 | 角色维护和权限分配是独立的操作权限 |
| 资源授权 | 查看全部账号授权、分配续期及撤销授权 | 平台权限分配不替代具体账号授权 |
| 审批 | 查看自己的申请、提交访问申请、查看全部申请及处理指定审批 | 审批人按审批权限筛选，不再要求角色类型必须为管理员 |
| 系统配置 | 查看及修改平台外观、查看及修改平台数据库配置 | 两项单独分配；每项同时包含该配置的查看和修改 |

部分管理页面需要其他模块的查看权限，系统会自动补齐依赖。例如分配账号授权需要查看用户、角色和全部资产；管理系统账号还需要查看授权。页面会显示实际勾选结果。

“审计 → 会话与录像”的菜单入口要求“查看全部会话”或“查看全部会话录像”。运维默认的“查看自己的会话”仅用于自身会话的数据范围，不授予审计菜单。命令、SQL / 协议和操作审计入口分别按对应权限显示；没有这些审计入口权限时，整个审计菜单隐藏。

勾选操作权限时自动勾选必要的查看权限；取消某个前置权限时，页面会取消依赖它的权限。服务端也会补齐依赖，不能通过直接调用接口获得一组缺少前置条件的权限。

## 三层权限分别检查

以 SSH 连接为例，用户必须同时满足：

1. 角色有“连接资源”平台权限。
2. 对所选资源系统账号有有效授权，或具备“免账号授权连接全部启用资源”权限。
3. 需要审批的资源有对应账号的有效审批，资源和账号均启用。

“查看全部资产”只扩大列表可见范围，不代表可以连接全部系统账号。查看或管理平台数据与连接目标资源是两类权限。

SSH/TELNET 连接后仍按角色和用户命令黑／白名单检查命令；平台权限不能绕过命令策略。SQL 执行权限还取决于目标数据库账号的实际读写权限。

## 常用配置示例

### 仅查看资产

选择“查看授权资产”；如需要查看全部资源则选择“查看全部资产”。不要勾选“连接资源”“新增及修改资产”或账号管理权限。

用户可查看相应资源信息，页面不展示连接、新增或修改入口；直接调用这些操作接口也会被拒绝。

### 授权资源的运维人员

选择查看总览、连接资源、查看自己的会话、终止自己的会话、查看自己的访问申请和提交访问申请。再通过“资产授权”为用户分配具体资源账号。需要命令控制时另配白名单。

### 专职审批人员

选择“查看全部申请及处理指定审批”。用户可被选为审批人并接收待审批消息，不必获得资源连接、用户管理或系统配置权限。指定审批和禁止自审的规则保持有效，其他审批人员也不能代替指定审批人处理新申请。

### 审计人员

按需要选择查看全部会话录像、命令审计、SQL / 协议审计和操作审计。录像权限会自动附带查看全部会话的权限，不会自动获得连接或终止会话权限。

### 外观维护人员

只选择“查看及修改平台外观”。用户看到系统配置中的外观部分，不会加载或展示数据库配置区域，也不能调用数据库配置接口。

## 管理边界与生效方式

- 内置管理员角色保留全部权限，不允许删减。需要受限管理员时新增自定义角色。
- 不能修改自己所属角色的平台权限，请由其他权限管理员处理，避免误操作导致自身权限失效。
- 只能分配自己已拥有的权限；不能修改权限范围超出自己的角色，也不能通过用户管理、MFA 或命令策略修改来接管更高权限用户。
- 角色仍有用户使用时不能删除；内置角色不可删除。
- 保存一组确实发生变化的权限后，对应角色用户的已有登录、待连接票据和所有协议活动会话失效，需要重新登录和连接。保存相同集合不会使会话失效。
- 空权限角色仍能登录、修改自己的密码、退出，以及查看自己的审批结果消息；没有其他平台功能菜单。
- 菜单和操作按钮按权限显示，HTTP 接口及协议 WebSocket 同时在服务端校验，手动输入地址不能绕过权限。
- 权限授予、撤销和保存会写入操作审计，记录角色 ID、具体权限代码和操作者。

接口提供 `GET /api/permissions` 获取权限目录、`GET /api/roles` 查看角色权限及 `PUT /api/roles/{角色ID}/permissions` 保存权限，均要求相应平台权限及正常登录。保存请求示例：

```json
{
  "permissions": ["assets.view", "sessions.connect", "sessions.view"]
}
```

返回角色数据中的 `permissions` 是补齐依赖后的实际权限集合。未知权限代码会被拒绝。

## 验证建议

使用一个单独的测试用户分配目标角色，重新登录后逐项确认菜单、查看范围、写操作和连接能力。在已有权限用户下打开的旧页面可能仍有旧按钮；服务端会按新权限拒绝请求，重新登录后页面与实际权限一致。
