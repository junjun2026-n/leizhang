## 认识平台与账号

堡垒机统一保存目标资源的连接配置，通过平台用户身份进行授权、访问审批、会话连接和审计。用户通常不需要知道目标资源的实际密码。

请区分以下三类账号：

| 账号类型 | 配置位置 | 用途 | 示例 |
| --- | --- | --- | --- |
| 平台用户 | 用户管理 | 登录堡垒机，作为申请人、审批人和审计操作者 | `zhangsan` |
| 资源系统账号 | 系统账号、资产管理 | 登录目标服务器、设备、数据库或网站 | Linux 的 `ops`、数据库的 `db_reader` |
| 平台数据库账号 | 系统配置中的 PostgreSQL 数据库 | 供堡垒机服务存储平台数据 | 专用 PostgreSQL 运行账号 |

修改平台登录密码不会改变资源系统账号密码。添加资源系统账号只是保存已有账号的连接凭据，不会在远程系统上自动创建账号。

平台角色基于三种初始权限类型，以下为未自定义平台权限时的默认行为：

| 功能 | 管理员 | 运维人员 | 审计员 |
| --- | --- | --- | --- |
| 用户、角色、资产、系统账号管理 | 可以 | 不可以 | 不可以 |
| 分配或撤销资源账号授权 | 可以 | 不可以 | 不可以 |
| 连接资源 | 启用资源的账号，无需单独授权；仍受访问审批和命令策略约束 | 仅有效授权账号，且须满足审批要求 | 不可以 |
| 审批访问申请 | 可以处理指定给自己的申请，不可自审 | 不可以 | 不可以 |
| 查看会话列表 | 全部 | 自己的会话 | 全部 |
| 主动终止会话 | 全部活动会话 | 自己的活动会话 | 界面不提供终止操作 |
| 查看录像及命令、SQL、操作审计 | 可以 | 不可以 | 可以 |
| 系统配置 | 可以 | 不可以 | 不可以 |

自定义角色选择其中一种初始权限类型，再设置角色名称、说明和命令策略。进入“权限管理”可按角色逐项分配平台功能的查看和操作权限，实际能力以所分配权限为准；详见[平台权限管理](permissions.zh-CN.md)。本手册下文所称管理员、运维人员和审计员，除特别说明外描述默认权限；自定义后需具有相应操作权限。

## 首次使用与登录

### 管理员准备

1. 确认堡垒机已启动，并可访问其 PostgreSQL 数据库。
2. 确认堡垒机服务器能访问目标资源的地址和协议端口。VNC 默认本机直连；RDP 的目标连通性取决于 guacd 网关所在主机。
3. 获取部署人员提供的访问地址和平台账号。
4. 生产环境使用管理员配置的 HTTPS 域名；局域网测试可使用已允许的 HTTP 地址。

本机访问示例：`http://127.0.0.1:8200/`。其他电脑访问示例：`http://192.168.17.127:8200/`，前提是该 IP 属于堡垒机服务器、网络可达且已加入允许的访问源。

`0.0.0.0` 是服务监听地址，不能作为浏览器访问地址。其他电脑上的 `127.0.0.1` 指向其自身，也不能用于访问堡垒机服务器。

### 登录步骤

1. 打开访问地址，输入平台用户名和平台密码。
2. 未启用 MFA 的账号直接点击“登录”。
3. 已启用 MFA 的账号点击“已启用 MFA？填写验证码”，输入身份验证器当前的六位动态验证码后登录。
4. 登录后确认右上角用户名和中文角色名称。
5. 新用户进入“修改密码”，设置自己的密码；新密码至少 12 位。修改成功后需要重新登录。

密码输入框旁的眼睛图标可以显示或隐藏本次输入内容。它不会读取或展示后台已保存的资源密码。

平台没有通用默认账号密码。新部署由部署人员创建管理员；本工作区初始管理员信息曾保存在受权限保护的 `runtime/initial-admin.txt`，以部署人员的实际交付为准。

| 资源管理 → 资产授权 | 按平台用户和资源系统账号分配有效期、续期或撤权 |

| 用户与权限 → 角色管理 | 新增、编辑角色及配置角色命令策略 |
| 用户与权限 → 权限管理 | 按角色勾选平台功能及操作权限，保存后相关用户重新登录 |
| 访问审批 | 查看申请、审批结果，处理待审批事项 |

| 系统配置 | 修改平台外观及平台 PostgreSQL 连接 |

实际菜单按角色权限显示。“资源管理”“用户与权限”和“审计”菜单可点击展开或收起，仅显示当前用户有权限访问的子菜单；没有任何子菜单权限时隐藏对应的整个菜单。

所有业务弹窗统一使用右上角 **×** 关闭，不再提供底部“关闭／取消”按钮。关闭表单不会保存尚未提交的内容；关闭终端、SQL 或远程桌面会断开当前连接；关闭录像会停止回放。表单中的“保存”、审批中的“通过／拒绝”仍需明确点击才执行。

删除系统账号、撤销资源授权和终止会话同样使用平台确认弹窗。点击右上角 × 放弃操作，只有点击“确认删除”“确认撤销”或“确认终止”才执行。

## 用户管理与多因素认证

### 新增和维护平台用户

管理员进入“用户管理”，点击“新增用户”，填写用户名、初始密码并选择角色。用户名为 3～80 位，可使用字母、数字及 `_ . @ -`，初始密码至少 12 位。

用户行的常用操作：

- “角色 / 启停”：修改所属角色及是否启用。管理员不能在这里修改自己的角色或停用自己。
- “命令黑 / 白名单”：设置此用户的 SSH/TELNET 命令规则，可查看其所属角色的规则。
- “开启 MFA / 关闭 MFA”：管理该账号的动态验证码要求。

修改用户角色或启停状态会使该用户已有登录失效，并终止其待连接及活动会话。请在变更前安排好正在进行的操作。

### 开启 MFA

1. 管理员在用户行点击“开启 MFA”。
2. 在可信身份验证器中添加基于时间的 TOTP 账号，录入弹窗中的密钥。
3. 输入身份验证器生成的六位动态验证码，点击“确认开启”。
4. 确认页面显示 MFA 已开启。

绑定配置有效期为 10 分钟，只有验证码验证成功才生效。密钥仅在绑定时展示，应通过受控方式交给对应用户，不要放入普通聊天群或日志。

启停 MFA 会注销该用户的其他登录；管理员操作自身时保留当前登录。身份验证器丢失时，由管理员关闭并重新绑定，或由部署人员按运维手册执行本地 MFA 重置。

## 角色管理

### 新增角色

1. 管理员进入“角色管理”，点击“新增角色”。
2. 填写角色名称，例如“生产巡检人员”。
3. 选择权限类型，例如“运维人员”。
4. 填写说明，按需选择命令策略和规则。
5. 点击“保存角色”。
6. 进入“用户管理”，通过“角色 / 启停”将该角色分配给用户；新增用户时也可直接选择。

### 编辑和删除

点击角色行“编辑”，可修改名称、说明和命令策略。内置管理员、运维人员、审计员角色不可删除，也不可改变其权限类型。自定义角色仍有用户使用时不能删除，应先为用户分配其他角色。

角色列表的“分配平台权限”或左侧“权限管理”提供功能分组勾选，支持只读、管理、审批和审计等组合。内置管理员固定保留全部权限；不能调整自己所属角色的权限，也不能向他人分配超出自身范围的权限。权限变更会使该角色用户的登录和各协议会话失效，需重新登录；普通角色名称或说明修改不受此规则影响。

修改角色名称或说明不终止会话；修改角色命令策略会终止所属用户的现有 SSH/TELNET 会话。修改自定义角色权限类型会同步更新所属用户的权限、注销其登录并终止全部协议会话。不能通过编辑角色改变自己的权限类型。

## 资产和系统账号管理

### 新增资产

管理员进入“资产管理 → 新增资产”，按实际协议填写配置：

| 字段 | 填写方式 |
| --- | --- |
| 协议 | SSH、TELNET、RDP、VNC、HTTP / HTTPS、PostgreSQL 或 MySQL / MariaDB |
| 资产名称 | 便于识别的唯一名称，如“生产应用服务器” |
| 地址和端口 | 从堡垒机或网关可达的目标地址及实际服务端口 |
| 系统账号、认证方式和凭据 | 目标资源上已存在的账号，SSH 支持密码或未加口令私钥 |
| 数据库名称 | PostgreSQL、MySQL/MariaDB 连接的目标数据库 |
| Windows 域 | RDP 所需域，没有域时按实际配置留空 |
| HTTP 协议和路径 | 选择 HTTP 或 HTTPS，填写站内路径，例如 `/` |
| 启用 | 控制资源是否可用 |
| 需要审批 | 勾选后，每位用户连接前须有对应账号的有效审批 |
| 校验 SSH 主机公钥 | SSH 的可选服务器身份核验 |
| 校验 TLS | 对支持的协议校验目标证书，目标需具备相应 TLS 配置 |

已保存资产不能直接切换协议；应为新协议新增资源，保留历史会话的协议和身份信息。

### SSH 主机公钥核验

开启“校验 SSH 主机公钥”后，提供可信的服务器公钥。可以点击“获取主机公钥”，再通过目标服务器控制台核验 SHA256 指纹，一致后勾选确认并使用。

目标服务器控制台的常用核验命令：

```sh
cat /etc/ssh/ssh_host_ed25519_key.pub
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

这里需要的是服务器主机公钥，不是登录用户的 `authorized_keys`，也不是用户私钥。关闭该选项后不核验服务器身份。

### 管理多个系统账号

1. 在资源行点击“系统账号”，或进入左侧“系统账号”。
2. 点击“新增系统账号”，选择所属资源并填写账号和凭据。
3. 在“资产授权”中分别授权，不同账号可以分配给不同平台用户。

例如同一服务器保存 `developer` 和 `ops`，只给开发人员授权 `developer`，并不会使其获得 `ops` 的访问权限。

修改已有账号时，凭据留空保留原值。停用账号、更换用户名或凭据会终止该账号的当前会话。删除账号会撤销相关授权和未结束审批，保留历史会话、录像和审计；重新添加同名账号不会恢复此前授权。

“系统账号”页面支持资源、状态和关键字筛选，关键字可匹配账号、资源、地址及授权用户。筛选后可点击“重置筛选”恢复条件。

## 资源授权与到期管理

普通运维用户需要取得具体系统账号的有效授权。管理员的全局资源访问权限不能用来验证普通用户的授权边界。

### 新增授权

1. 管理员进入“资产授权”。
2. 选择资源，再选择具体系统账号。
3. 勾选一个或多个已启用的平台用户。
4. 设置有效小时，范围为 1～8760 小时。
5. 点击“保存所选用户授权”。

同一资源账号可以授权给多人。重新保存只调整所选用户与所选账号的授权，其他用户及账号不受影响。停用用户和审计员不可授权或续期。

### 续期和撤权

| 操作 | 效果 |
| --- | --- |
| 修改有效期 | 单条授权从当前时间重新设置有效小时 |
| 批量续期 | 有效授权从原到期时间增加时长；已过期授权从当前时间增加 |
| 撤销或批量撤销 | 撤销选定账号授权，终止对应会话，并作废相应未结束审批 |

批量操作单次最多 100 项；重新筛选会清空勾选。批量操作会先检查整批记录，遇到无效项时整批失败，应刷新列表后重新选择。

账号授权和访问审批是两项独立条件。授权续期不会自动续期审批；撤权后重新授权，也需要按资源审批要求重新申请。

## 访问申请与审批消息

### 用户申请

1. 运维人员在“资产管理”找到已授权资源，点击“申请访问”。
2. 有多个可用账号时，先选择系统账号。
3. 选择其他已启用且具有访问审批权限的用户作为审批人，默认管理员具有此权限。
4. 填写至少 5 个字的访问原因，设置 1～8 小时访问时长。
5. 提交后，在“访问审批”中查看进度。

审批到期时间从提交申请时开始计算，不是从审批通过或首次连接时开始计算。审批等待时间过长可能导致批准后可用时长不足，应按实际需要重新申请。

### 管理员审批

1. 指定审批人登录后查看右上角小喇叭或进入“访问审批”。
2. 核对申请人、资源、系统账号、访问原因和到期时间。
3. 点击“通过”或“拒绝”。

新申请只能由指定审批人处理，其他管理员不能代办，也不能审批自己的申请。管理员本人访问启用审批的资源同样需要其他管理员审批。只有一个管理员时，应先新增另一个管理员，或按管理制度配置无需审批的资源。

启用平台权限分配后，可以为专职审批角色授予审批权限，该角色用户也能成为审批人，无需同时获得用户管理或资源连接权限。

### 消息提醒

小喇叭显示待处理或未读消息数量。审批人可跳转到待审批事项；申请人可查看“通过”或“不通过”的结果，并点击“标为已读”。标为已读只清除未读状态，不删除申请。

消息没有定时轮询或主动推送。登录、页面刷新、点击消息及相关审批页面操作时更新；页面长时间未刷新时，数字可能不是最新状态。

审批通过后，回到“资产管理”点击“连接”。审批绑定具体资源账号，不可用同一资源另一个账号的审批代替。

## 各协议连接方法

### 连接前检查

确认资源和系统账号均启用，普通用户的账号授权未过期，且需要审批的资源已有未过期审批。堡垒机到目标的网络、服务端口和凭据也应有效。

| 协议 | 默认端口 | 必要条件或附加组件 |
| --- | --- | --- |
| SSH | 22 | SSH 服务和密码或未加口令私钥 |
| TELNET | 23 | TELNET 服务及可识别的登录提示 |
| RDP | 3389 | guacd 网关、目标远程桌面服务 |
| VNC | 5900 | 目标 VNC 服务；默认由堡垒机直接连接 |
| HTTP | 80 | 平台服务器的 Playwright 浏览器环境 |
| HTTPS | 通常 443 | 在 HTTP 资源中选择 HTTPS，并手动设置实际端口 |
| PostgreSQL | 5432 | 数据库名称、目标数据库账号和访问规则 |
| MySQL / MariaDB | 3306 | 数据库名称、目标数据库账号和访问规则 |

端口仅为常用默认值，应以目标实际配置为准。

### SSH

点击“连接”后打开网页终端。未配置命令策略时提供交互终端，可使用目标账号具备权限的命令；输出加密录制。配置命令策略后改为受控逐条命令模式，具体限制见下一章。

完成操作后点击右上角 × 断开连接。不应仅通过切换侧栏来假定后台连接已经关闭，可在“会话与录像”中确认状态。

### TELNET

使用目标已有账号和密码。平台识别常见 `login:`、`username:`、`password:` 提示并自动登录。设备使用定制认证提示、多轮认证或特殊编码时可能需要适配。

受控命令模式要求自动登录后识别 `$`、`#` 或 `>` 等标准提示符。TELNET 上游传输为明文，适用于受控网络中的兼容设备。

### PostgreSQL

1. 新增 PostgreSQL 资产，填写地址、端口、数据库名和已存在的数据库账号。
2. 按目标配置选择“校验 TLS”。勾选时使用证书及主机名校验，目标需要启用 SSL 并具有可信证书。
3. 完成授权和审批后点击“连接”。
4. 等待“已连接”，在 SQL 输入区填写一条语句，点击“执行 SQL”。

连通性验证可使用以下只读语句：

```sql
SELECT 1 AS connection_ok;
```

目标未启用 SSL 但勾选“校验 TLS”时会连接失败。应为目标配置 SSL；如环境明确允许非 TLS 连接，可取消该资源的“校验 TLS”后保存重连。PostgreSQL 未校验模式优先尝试 SSL，目标不支持时可使用非 TLS 连接，不代表仍在校验证书。

### MySQL 和 MariaDB

选择“MySQL / MariaDB”协议，填写数据库名称、账号和实际端口。启用 TLS 校验时需目标提供 TLS，且证书 CA 和主机名校验通过。连接后与 PostgreSQL 一样，在网页控制台逐条执行 SQL。

SQL 控制台的共同规则：每次一条语句，执行超时上限为 30 秒；结果最多展示 500 行、约 1 MiB。写入操作立即提交，没有跨多次点击维持事务的操作界面。PostgreSQL 语句出错后可继续使用连接；MySQL 出错后关闭连接，需要重连。

SQL 审计只覆盖通过本平台 SQL 控制台执行的语句，不审计外部数据库客户端、其他应用或数据库内部作业。连接中断时操作可能已经提交，应先核对目标数据，避免直接重复写入。

### RDP 和 VNC

RDP 需要 Apache Guacamole 的 guacd 网关，部署人员配置 `GUACD_HOST`、`GUACD_PORT`。VNC 默认由堡垒机直接连接目标 VNC 端口，不需要 guacd；SSH 弹窗的 VNC 页签可以选择已授权的 VNC 资源账号。

RDP 填写目标账号、密码及需要的 Windows 域；VNC 按目标认证方式填写凭据。打开连接后点击画面再进行键盘和鼠标操作。画面加密录像，关闭弹窗断开连接。

当前关闭剪贴板、文件盘映射、打印和音频转发。RDP 的网关未部署或未连通时会提示网关不可用；VNC 本机直连时检查目标端口和密码。实际目标主机均需连接验收。

### HTTP 和 HTTPS

平台服务器运行隔离浏览器，将远端页面画面传给用户。选择协议、端口和站内路径后连接，点击画面操作；中文或多行内容可在文字框输入后点击“发送文字”。

资源账号用于 HTTP Basic 认证；网站自己的表单登录可在远程画面中手动完成。平台只允许当前资源同源请求，阻止外站、WebSocket、弹窗和下载，因此依赖外部 CDN、第三方登录或 WebSocket 的站点可能无法完整使用。

Windows 默认使用已安装的 Microsoft Edge；Linux 需部署 Playwright Chromium 环境。具体安装方式见[多协议说明](protocols.zh-CN.md)。

## 命令黑名单与白名单

### 配置入口

- 角色统一规则：“角色管理 → 编辑 → SSH / TELNET 命令策略”。
- 个别用户规则：“用户管理 → 命令黑 / 白名单”。

只限制 SSH/TELNET，不影响 SQL、RDP、VNC 或 HTTP。默认“不限制”保留普通交互终端。

| 模式 | 行为 |
| --- | --- |
| 不限制 | 该层不增加命令规则，用户仍受其他层的规则约束 |
| 黑名单 | 命中任意黑名单规则即拒绝；黑名单至少填写一条规则 |
| 白名单 | 只有匹配白名单的命令可执行；空白名单拒绝全部命令 |

### 规则格式

每行一条，区分大小写；支持 `*`、`?` 和字符组通配符。最多 100 条，每条 1～256 个字符。

黑名单示例：

```text
rm
reboot
shutdown *
```

单独写 `rm` 会匹配该命令的全部参数，也会匹配 `/bin/rm`。带参数的规则按完整命令匹配，例如 `shutdown *`。

巡检白名单示例：

```text
whoami
hostname
df -h
ls -l /var/log
```

其中 `whoami` 和 `hostname` 是命令名称规则，会允许其参数。需要更精确的参数约束时使用包含参数的完整命令规则。

### 规则共同生效

角色与用户策略同时检查，拒绝优先。任何黑名单命中即拒绝；每份启用的白名单都必须匹配。

例如，角色白名单有 `whoami`、`df -h`，用户黑名单有 `df`：该用户可以执行 `whoami`，不能执行 `df -h`。用户选择“不限制”不会解除角色限制。

### 受控终端使用方式

启用任一层命令规则后，终端会显示“命令策略已启用”和 `policy>` 提示。输入完整单条命令，按回车，服务端检查通过后才发送到目标；拒绝时显示原因并记录命令审计。

受控模式不支持管道、重定向、变量和命令替换，不转发历史键、补全或终端控制序列。解释器、交互编辑器、命令代理及可修改 shell 执行行为的部分内置命令会被禁止，即使白名单中写入这些命令也不会放行。

SSH 每条命令使用独立的非交互执行通道，不保留 `cd`、环境变量等状态；应使用绝对路径。单条命令通常最多执行 60 秒，若配置的空闲限制更短则使用更短时间。命令参数按字面值传递，不能依赖远端 shell 展开文件通配符。

保存用户策略或修改角色策略会终止受影响的待连接和活动 SSH/TELNET 会话，需重连使用。其他协议不因单独修改命令策略而被终止。

命令规则控制网关提交的命令，无法判断程序内部行为。严格限制应使用精确白名单、权限受限的目标账号，以及目标系统的文件和执行权限。自建程序、复制改名程序、远端别名和启动脚本仍需要目标系统约束。

## 会话录像与审计

### 会话状态和终止

“会话与录像”显示最近最多 200 条可见会话，包含平台用户、资源、协议、系统账号、起止时间和说明。

| 状态 | 含义 |
| --- | --- |
| `pending` | 已申请连接，等待使用连接票据 |
| `active` | 活动连接 |
| `closed` | 会话结束 |
| `failed` | 连接或会话执行失败，查看说明及日志 |
| `terminated` | 被主动终止、撤权或策略变更终止 |
| `interrupted` | 服务重启等导致原会话中断 |

管理员可终止活动会话，普通用户可终止自己的会话。授权过期、审批过期、账号停用或相关权限变化也会使连接失效，通常在下一次周期性会话检查时断开。

默认每用户最多同时开启 5 个有效待连接或活动会话。连接票据仅有效 30 秒且只能使用一次，过期后应重新点击“连接”。

### 录像回放

管理员或审计员在会话行点击“回放”：

- SSH/TELNET：可按原始时间播放，或显示完整终端输出。
- RDP/VNC：按原始时间回放已保存的远程画面。
- HTTP：回放已保存的页面画面。
- SQL：查看该会话的 SQL 审计记录，不提供终端视频。

SSH/TELNET 录像保存终端输出，远端回显也包含在其中；未回显输入不保证出现在普通终端录像中。启用命令策略的会话另外保存逐条命令审计。HTTP/桌面录像可能包含页面或业务敏感信息。

### 命令审计

“命令审计”可按 SSH、TELNET 筛选，通过关联操作 ID 对应命令提交与后续事件：

| 事件 | 含义 |
| --- | --- |
| 提交命令 | 网关收到准备执行的完整命令 |
| 拒绝执行 | 命令命中策略或不满足受控模式要求，未向目标转发 |
| 执行结束 | SSH 命令返回退出状态或执行超时 |
| 已转发（TELNET） | 命令已写入 TELNET 连接，不表示目标执行成功 |

只有受控模式生成这些逐条命令记录；普通交互模式继续保存输出录像。TELNET 执行结果需结合终端录像检查。

### SQL 与协议审计

“SQL / 协议审计”可按协议筛选，也可从具体会话进入：

- SQL 在执行前记录语句，执行结束后记录错误、耗时、影响行数等，两类记录用关联操作 ID 配对；不保存查询返回的数据行。
- HTTP 记录请求方法、URL 和响应状态，隐藏 URL 查询参数，不记录请求体、Cookie 或认证头；画面录像是另一类记录。
- 其他协议按实际实现提供对应事件或录像。

### 操作审计

“操作审计”记录登录、用户角色维护、资产和授权变更、审批、会话终止及审计读取等事件，按页查看。管理员和审计员可访问，审计读取本身也会留痕。

审计及录像采用加密和只追加保护，应用不提供删除、修改或清空审计记录的功能。留存、归档和容量管理由部署人员按制度处理。

## 系统配置

### 平台外观

管理员进入“系统配置”，可设置平台名称、说明、LOGO、明亮或深色风格、主题颜色、字体及字号。字体实际效果取决于客户端已安装字体。

LOGO 支持 PNG、JPEG、WebP，上传源文件最多 5 MB，页面自动缩小至最长边 256px，保存内容最多 32 KB。点击“预览外观”只预览；“取消预览”恢复已保存外观；点击“保存外观”才持久保存。其他已打开的客户端刷新页面后加载新配置。

### 平台数据库配置

该区域设置的是堡垒机自身的 PostgreSQL 存储，和“资产管理”中的数据库资源不同。

1. 查看“当前连接”和待生效配置。
2. 填写数据库地址、端口、数据库名、运行账号、密码及 SSL 模式。
3. 点击“测试连接”，确认目标可连接及平台表检查结果。
4. 确保原有数据和匹配的 `MASTER_KEY` 已完成迁移，再点击“保存数据库配置”。
5. 由部署人员重启服务并检查登录、授权、凭据和录像。

密码留空保留已配置密码，更换主机、端口或账号必须重新填写密码。保存只写配置，不自动迁移数据、创建目标数据库或重启服务。

配置写入 `.env`，重启后生效。若服务管理器或容器通过环境变量提供 `DATABASE_URL`，还要同步修改该环境变量，因为它优先于 `.env`。测试连接不能代替完整的数据和权限验收。

## 启动维护与备份

以下操作由部署人员执行，命令工作目录为 `leizhang`。已安装依赖和配置数据库后，Windows 常规启动方式：

```powershell
cd C:\20260501\qionghai\leizhang
.\start.ps1
```

脚本默认监听 `0.0.0.0:8200`。项目本地 PostgreSQL 环境会先启动本地数据库并执行升级；外部数据库环境需要先用迁移账号完成升级。不要在服务已监听 8200 时重复启动另一份进程。

Linux 启动方式：

```sh
cd /path/to/leizhang
sh start.sh
```

全新部署、Docker、管理员创建和 HTTPS 配置见[项目说明](../README.md)及[生产部署与运维](operations.zh-CN.md)。

常用运行参数：

| 参数 | 默认值或作用 |
| --- | --- |
| `PUBLIC_ORIGIN` | 主访问源，必须与用户访问的协议、主机和端口匹配 |
| `ALLOWED_ORIGINS` | 额外明确允许的访问源，逗号分隔，不支持通配符 |
| `COOKIE_SECURE` | 生产 HTTPS 使用 `true`；本地 HTTP 测试需匹配配置 |
| `SESSION_MINUTES` | 平台登录有效期，默认 480 分钟 |
| `SSH_SESSION_SECONDS` | 会话总时长上限，默认 3600 秒，也用于其他协议的共享会话限制 |
| `SSH_IDLE_SECONDS` | 空闲上限，默认 900 秒 |
| `MAX_RECORDING_BYTES` | 每会话录制容量限制，默认 20971520 字节，即 20 MiB |
| `GUACD_HOST` / `GUACD_PORT` | 远程桌面网关地址，默认 `127.0.0.1:4822` |
| `HTTP_BROWSER_CHANNEL` | HTTP 隔离浏览器通道，Windows 默认 `msedge` |

修改运行配置后需要重启。平台当前按单实例、单 Uvicorn worker 部署，重启会中断所有活动连接。

维护时检查 `/health/live` 和 `/health/ready`；健康请求的 Host 同样要符合允许的访问源。查看对应启动方式下的应用日志；本工作区后台启动日志在上级 `logs` 目录，其他部署以服务管理器或容器日志为准。

备份至少包含 PostgreSQL 数据及独立受控保存的 `MASTER_KEY`。主密钥用于解密资源凭据、MFA 和录像，不能用新生成的密钥替代。升级前备份，并在隔离环境验证恢复；仅有数据库备份而没有匹配密钥，无法恢复加密内容的可用性。

## 常见问题处理

| 现象 | 检查与处理 |
| --- | --- |
| 浏览器打不开 | 确认服务已启动、服务器 IP 正确、8200 或反向代理端口可达；其他电脑不要使用 `127.0.0.1` |
| 访问域名不匹配、请求来源不匹配 | 检查 `PUBLIC_ORIGIN`、`ALLOWED_ORIGINS` 是否包含实际协议、主机和端口，修改后重启 |
| 登录成功后仍回到登录页 | 检查访问源和 Cookie 配置；HTTP 测试环境若设置安全 Cookie，浏览器可能无法正常携带 |
| 用户看不到资产或账号 | 检查用户、资产和系统账号是否启用，具体账号授权是否有效；审计员不能连接 |
| 已授权但提示先审批 | 授权不等于审批；检查是否针对同一系统账号申请并通过，且审批未过期 |
| 无可用审批人 | 必须有其他已启用的管理员，不能选择自己 |
| 审批通过后很快过期 | 到期时间从提交申请时开始计算，重新申请合适的时长 |
| 小喇叭数字未更新 | 无定时推送；刷新页面或点击消息，处理结果后可标为已读 |
| PostgreSQL 提示未启用 SSL | 资源勾选了 TLS 校验但目标没有 SSL；配置目标 SSL，或在允许非 TLS 的环境取消校验后重连 |
| TLS 证书校验失败 | 检查可信 CA、证书有效期及资源地址是否匹配证书主机名 |
| SSH 主机公钥不匹配 | 从服务器控制台重新核验主机公钥和指纹，确认变更来源后更新资源配置 |
| SSH 上游认证失败 | 检查资源系统用户名、密码或私钥、账号启用状态及目标登录限制 |
| TELNET 无法自动登录 | 检查目标提示符、认证轮次和编码是否受支持；受控模式还需标准命令提示符 |
| RDP/VNC 提示网关未连接 | 部署并检查 guacd、网关地址和端口，确认网关能访问目标服务 |
| HTTP 页面不完整或登录失败 | 检查浏览器运行环境，确认页面是否依赖被阻止的外站、WebSocket 或第三方登录 |
| 命令在白名单里仍被拒绝 | 同时检查角色白名单、用户白名单、所有黑名单和受控模式禁止的语法／程序 |
| 设置不限制后仍受控 | 用户“不限制”不会覆盖角色策略，检查所属角色配置 |
| 命令审计没有记录 | 确认是启用策略后的 SSH/TELNET 会话；普通交互模式查看录像，旧会话不会补录命令事件 |
| SQL 执行失败或结果截断 | 每次只执行一条语句，检查数据库权限、30 秒限制及结果行数／容量上限；MySQL 出错后重连 |
| 会话突然断开 | 检查授权、审批、登录有效期、策略变更、强制终止、空闲、总时长、录像容量和服务重启日志 |
| 录像无法解密 | 核对运行环境是否使用原数据库对应的 `MASTER_KEY`，不要重新生成密钥尝试恢复 |
| 页面仍显示旧按钮或旧样式 | 刷新页面；仍未更新时使用 Ctrl+F5，并确认连接的是正确服务器和端口 |

向管理员反馈连接问题时，提供发生时间、资源名称、协议、系统账号、会话 ID 和完整错误提示；不要附带密码、私钥、MFA 密钥或 `.env` 内容。

## 完整操作示例

### 示例一：给巡检人员授权 SSH

1. 在“角色管理”新增“生产巡检”，权限类型选“运维人员”，白名单填写 `whoami`、`hostname`、`df -h`。
2. 在“用户管理”创建 `inspector`，分配“生产巡检”角色。
3. 在“资产管理”新增 SSH 资源，填写目标地址，并保存目标已有的低权限系统账号 `ops_readonly`。
4. 在“资产授权”选择该资源和 `ops_readonly`，授权给 `inspector`，例如有效 24 小时。
5. `inspector` 登录后修改初始密码，申请访问该账号，选择指定管理员并填写巡检原因。
6. 指定管理员审批通过，用户在小喇叭中查看“通过”。
7. 用户连接终端，执行 `whoami`、`df -h`；执行不在白名单的命令应被拒绝。
8. 完成后点击右上角 ×。管理员或审计员在“命令审计”及“会话与录像”中核对记录。

### 示例二：通过控制台访问 PostgreSQL

1. 目标数据库管理员先创建权限受限的数据库账号，并允许堡垒机来源访问。
2. 堡垒机管理员新增 PostgreSQL 资源，填写数据库名、端口、系统账号和符合目标环境的 TLS 设置。
3. 将该数据库账号授权给所需平台用户，按资源要求完成审批。
4. 用户连接后执行 `SELECT 1 AS connection_ok;`，确认结果为 `1`。
5. 用户按数据库账号权限逐条执行 SQL，完成后点击右上角 ×。
6. 管理员或审计员进入“SQL / 协议审计”，按 PostgreSQL 或对应会话核对 SQL、结果状态和耗时。

这个例子中的 SQL 不受 SSH/TELNET 命令白名单控制。数据库读写权限应在目标数据库中授予和限制。

# 管理员重置普通用户密码

管理员登录后，在用户管理的普通用户行点击“重置密码”，输入至少 12 位新密码并再次确认，点击“确认重置”。无需原密码。仅管理员且具有用户管理权限可操作，不能通过此入口重置管理员或自己的密码；自己的密码使用“修改密码”。

保存后目标用户现有登录失效，活动/待连接会话终止，MFA 设置保持不变。操作审计记录 `user_password_reset` 及操作者、目标用户，不记录新密码。新密码应通过受控渠道交给用户。
